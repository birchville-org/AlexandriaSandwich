# Plan 04-02: Path B Visual Editor — Inline PDF Text-Layer Correction UI

<objective>
Extend the FastAPI Web UI (built in 04-01) with a visual editor that allows
the user to review and correct the invisible text layer of sandwich PDFs
inline in the browser. This wraps the existing `pdf_text_correct.py` CLI
(dump → init → edit → replace) into a browser-based workflow.
</objective>

<execution_context>
The Path B CLI (`scripts/pdf_text_correct.py`) already supports:
  - `dump` — extract text from sandwich PDF via pdftotext
  - `init` — build a corrections template (OLD→NEW JSON)
  - `replace` — apply corrections into the PDF text layer, producing `.pathb.pdf`

The Web UI (`ui/main.py`) already has dashboard, upload, job detail, and
download routes. It runs in the `alexandria_ui` container on alex.local:8080
with `/data` mounted. The worker container (`alexandria_worker`) has
`pdftotext`, `pikepdf`, and `pdf_text_correct.py` available.

**Architecture decision:** The UI container calls `pdf_text_correct.py` via
`docker exec alexandria_worker` (same pattern as the n8n workflow) rather than
bundling pikepdf/poppler into the UI container. This keeps the UI slim.
Alternatively, if the UI container can run the script directly (pikepdf is
pip-installable), we install pikepdf in the UI container and call the script
locally — simpler, no docker exec needed. **Preferred: install pikepdf in UI
container** (it's a pure-Python wheel, no system deps beyond what slim provides).
pdftotext (poppler-utils) needs apt-get in the Dockerfile.
</execution_context>

<context>
<interfaces>
## Existing CLI interface (pdf_text_correct.py)

```
# Extract text from sandwich PDF
python3 pdf_text_correct.py dump <pdf> --json -o <output.json>

# Init corrections template
python3 pdf_text_correct.py init <pdf> -o <corrections.json>

# Apply corrections
python3 pdf_text_correct.py replace <pdf> -c <corrections.json> -o <output.pdf> --json
```

## Existing Web UI routes (ui/main.py)

```
GET  /                          — dashboard
GET  /upload                    — upload form
POST /upload                    — upload + trigger
GET  /jobs/{job}                — job detail
POST /jobs/{job}/trigger        — trigger n8n pipeline
GET  /browse/{kind}/{job}/{fn}  — browse file
GET  /download/{kind}/{job}/{fn}— download file
GET  /health                    — health check
```

## New routes to add

```
GET  /jobs/{job}/edit              — visual editor page (extracted text, editable)
POST /jobs/{job}/correct           — apply corrections, produce pathb.pdf
GET  /jobs/{job}/preview/{page}     — render PDF page as PNG (via pdftoppm)
GET  /jobs/{job}/corrections       — view/download existing corrections JSON
```
</interfaces>
</context>

<threat_model>
- **Path traversal**: All file paths resolved through _safe_path() helper — no user-controlled path escapes /data
- **Malicious PDF**: pikepdf is robust against malformed PDFs; subprocess calls use shell=False
- **Large PDFs**: pdftoppm rendering at 150 DPI for preview — memory bounded, single page at a time
- **Corrections injection**: Corrections JSON is validated as dict[str,str] before passing to replace_in_pdf; no code execution from user input
</threat_model>
